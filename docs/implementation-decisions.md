# 实施决策与核心能力核验

日期：2026-11-14。输入规格为根目录交接文档，文档中的示例域名、预算和模型名称不作为生产配置。

## 核心选择

源码核验锁定 New API `v0.9.9-patch.4`，提交 `2df75d14a046aa67146d059ad37a61e7acc4715e`。源代码保存在被忽略的 `research/new-api`，其中未发现 AGENTS.md；未修改其源码、许可证、品牌或署名。源码及其 LICENSE 均保留在研究目录，运行镜像不包含它，也没有复制其中实现。

| 规格要求 | New API 源码核验 | 本项目处理与证据 |
| --- | --- | --- |
| 令牌组、模型限制、到期 | 原生支持，需配置 | `model/token.go` 定义 Group、ModelLimits、ExpiredTime；本项目独立绑定 Key→成员→组，A01–A07 集成测试 |
| 个人 Key 只显示一次且不可逆存储 | 需修改 | `model/token.go:17` 的 Key 字段为可直接查询字符串，`GetTokenByKey` 按原值查询；本项目 HMAC-SHA256 摘要，随机熵 256 位，原值仅签发响应返回 |
| 上游凭证认证加密 | 需修改 | `model/channel.go:24` 的 Key 字段为字符串；本项目 Fernet 认证加密，主密钥独立受限文件 |
| 个人自然周期预算和组总预算原子检查 | 需修改 | 原生用户/令牌配额及路由分组不足以表示本项目成员周期和独立组总预算；本项目同一 PostgreSQL 事务锁定双预算周期并登记预留，A08 两类 30 并发竞争 |
| 覆盖最大输出的保守预留 | 需修改 | `relay/helper/price.go` 使用输入比例预扣，不能直接证明覆盖不同输出价格；本项目分别按输入未命中价与最大输出价预留 |
| 缺失 usage、断连和崩溃待核对 | 需修改并验证 | 本项目保留预留并阻止不确定资金再次使用；网络断连验收、SIGKILL 演练、幂等结算测试 |
| 管理员开通、管理 API | 原生支持部分，需关闭自助入口并扩展身份与幂等 | 本项目仅管理员会话可管理，不提供注册；A17、A22 |
| SSE 协议 | 原生支持，供应商格式仍需验证 | 本项目复用 SDK 的 SSE 解码，覆盖拆包、CRLF、注释、choices 含结束状态的 usage 和空 choices 独立 usage |

上述“原生支持”是锁定源码核验，不是 New API 运行验收；未在 New API 上运行两组模拟测试。因此不将它的路由、预算或存储描述为已通过本项目验收。

鉴权、缓存键、密钥存储、预算对象与准入、结算恢复都需要改动，超出小范围补丁。评估了 LiteLLM 的 [DeepSeek 适配](https://docs.litellm.ai/docs/providers/deepseek)：它可复用供应商协议，但采用其完整代理仍需核验并调整相同的预算与恢复语义。当前只开放两个文本 API，最终选择成熟 SDK 的窄协议适配，实验室逻辑集中在一个服务和一个账本。没有第二套开通服务账本或异步同步扣费链路。这个选择偏离“优先 New API”的工程默认值，保持交接文档的业务隔离、额度与密钥要求。

运行技术栈和直接依赖精确版本见 `pyproject.toml`；传递依赖及哈希见 `uv.lock`、`requirements.lock`。SDK 为 OpenAI Python SDK，但固定连接 DeepSeek，不需要 OpenAI 平台账号或凭证。SDK 自动重试设为 0，HTTP 重定向关闭，主机环境代理不用于上游请求。未实现通用多供应商协议转发器。

## 账本、锁和恢复

PostgreSQL 是唯一资金和身份来源。准入先用 FOR NO KEY UPDATE 锁项目组（保留互斥且兼容外键 Key Share 校验），重新读取身份和权限，再按组周期、成员周期的固定顺序锁双预算周期；结算使用相同周期锁顺序。多 Key 共享 membership 预算。周期按 Asia/Shanghai 自然日或自然月创建，数据库时间保存 UTC。预算类型创建后固定，调整上限保留已用和预留，原周期和历史不删除。跨周期请求结算原准入周期。

延迟优化迁移 `9d31b47fa820` 将持锁准入放入版本化 PostgreSQL 函数 `gateway_admit`，函数源码位于 `migrations/sql/0003_admit.sql`，通过 Alembic 安装，不能仅运行 `Base.metadata.create_all` 初始化服务。Python 按组以2ms窗口、最多64笔合并提交；每笔独立检查，拒绝项通过子事务回滚，成功项共用一次持久化提交，提交完成后才返回给各请求去调用上游。整批使用同一记录在 Call 上的自然周期/价格时刻，Key 到期仍按检查时的实时时间判断。提交失败不发送上游。客户端任务取消时，仅能证明尚未发送的请求按0费用释放；无法持久化释放时保留预留并记录告警。

进程内只缓存 Key 摘要到组/成员 ID 的路由提示（最多4096项、60秒），不缓存有效权限或余额；每次数据库准入重新确认禁用、轮换、过期、模型、凭证和预算。Redis I/O 在资金锁外执行，当前限制仍由数据库中的最新配置检查。已认证但因预算、并发或模型等原因拒绝的尝试也会占用 Redis 尝试频率；缓存提示刚失效的一次尝试可能计入频率，但不会绕过鉴权，拒绝后清除提示。PostgreSQL 的已接受请求限流独立保留。

结算保留逐笔原事务。进程内调度避免大量结算连接同时排队占用数据库池：有结算等待时，最多连续处理4批准入就让出一次结算机会；数据库锁仍保证正确性。持续高请求率下结算可能积压并占用并发额度，不能把突发首输出测试解释为持续吞吐承诺。未实现批量结算或内存队列异步扣费。

新请求从预留提交到结束保持 `reserved`，不再单独提交 `running`；该状态表示“已准入，可能已发送”，重启仍恢复为 `pending`。`admission_ms` 在完整提交后测量，随最终结算/待核对事务保存，避免为计时新增一次提交；强制崩溃时这一非资金指标可能缺失。SSE 每15秒发送下游保活注释，不将其计为首有效增量；上游连接空闲保留30秒。

并发数由持久化请求统计，包含 reserved、running、pending。Redis 只对短期尝试频率计数，PostgreSQL 额外检查最近 60 秒已接受请求，因此 Redis 清空不会刷新已接纳速率或运行并发。Redis 故障拒绝收费请求。不确定请求保守占用并发名额，人工核对结束后释放。

请求和双预留在调用前提交。每个请求只有一个上游尝试，不跨组回退。结算锁请求和双周期，以唯一账本操作及状态保证幂等。缺失/无效 usage、非 200 错误、超时和断连不能证明免费，进入 pending。已取得最终 usage 则按实际计量结算。结算数据库故障有限重试，失败时保留预留；启动恢复将未完成请求转为待核对。人工核对原因、账本与审计在同一事务提交。

进程使用 PostgreSQL 会话 advisory lock 限制为一个实例。部署必须单进程、单副本。SIGKILL 演练实际验证进行中的请求可恢复为 pending，无自动退款或重复结算。数据库暂时不可达期间产生的未完成状态，需要恢复数据库并重启网关，进入人工核对，不依赖 TTL 自动退款。

## 价格与预留边界

价格表固定供应商语义为 DeepSeek、内部币种 CNY；各公开模型映射到明确上游模型。每个版本保存生效起止、缓存命中/未命中/输出价格、估算标记和来源规则说明。发布新版本关闭旧版本区间，进行中的调用仍引用旧价格。

金额为整数微元；价格为微元/百万 Token。每笔请求将三个整数乘积相加后统一向上舍入到 1 微元。缓存命中是总输入子集，推理量是总输出子集，不再次累加。缺失 usage 与真正 0 Token 分别处理。

输入预估为整个已验证 JSON 的 UTF-8 字节数，加每消息64、固定256结构余量及64字节的服务器输出参数补充余量后乘2；未知缓存按未命中价，输出按服务器收紧的 max_tokens。它是保守估算，并非供应商 tokenizer 的数学成本证明。实际超预留时真实记账、允许余额为负并拒绝后续超预算请求，同时生成事件。

首版不自动复现高低峰、节假日及汇率；管理员核验后录入明确的保守价格包络，并保持“估算”标记。官方当前价格可能有时段及币种规则，不能把模拟价格作为官方价格。参考：[DeepSeek 价格](https://api-docs.deepseek.com/quick_start/pricing/)。不能宣称与官方账单逐笔精确一致或绝对零超支。

## 隐私与范围

不持久化提示词、回答、推理文本、函数参数或原始异常响应。用量只提取数值 Token 字段。Pydantic 错误不回显输入；未处理异常只记录类型和请求 ID，阻止 Uvicorn 默认堆栈泄露第三方响应。CSV 防公式注入。代理来源须显式信任，默认不信任转发头。

仅开放文本与客户端函数工具；图像、文件、内置付费工具、Responses 等路径和未知聊天参数明确拒绝。根据用户后续要求，现已补充预先导入名单的学生自助门户；仍无公开注册、支付或全局预算功能。全局预算为交接文档的可选扩展，目前不配置；已强制执行的预算为成员与项目组两层。

学生账号使用 Argon2 密码摘要，与管理员会话分离；初始会话仅可查询自身基础资料、改密或退出。学生领 Key 的成员身份由会话绑定，不能自行填写学号、组、模型、金额或到期来扩大权限；自助到期由成员上限限制。Key 签发与旧 Key 撤销在同一事务，原成员预算保持不变。重置密码撤销该学生全部会话和 Key；改密使用版本递增使旧会话失效，并重新签发当前会话。密码与 Key 原文不写入审计、幂等结果或数据库。

测试模式支持学号初始密码，生产模式只允许随机初始密码，以防已知学号造成首次登录被抢占。邮件重置采用管理员人工核实身份的流程，没有发送邮件或匿名重置接口。该门户来自本次用户新增需求，覆盖交接文档原本不提供学生门户的范围限制。

没有改动现有 GitLab 的 80/443、已有数据库、已有 Redis 或防火墙。真实公网或校园网入口、证书与旧 Key 迁移仍需实际安排。外部告警未配置，仅管理界面和安全运维日志可见。
