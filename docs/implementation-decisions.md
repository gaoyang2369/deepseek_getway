# 架构与关键约束

## 技术选择与模块

项目采用 FastAPI + OpenAI Python SDK（固定连接 DeepSeek）+ PostgreSQL + Redis。初期核验过 New API `v0.9.9-patch.4`（`2df75d14a046aa67146d059ad37a61e7acc4715e`）；个人 Key 摘要存储、成员/组双预算及不确定调用的恢复语义需要较多改动，因此选择独立实现窄协议网关。研究源码没有进入运行镜像，也未复制其实现。精确依赖及哈希在 `pyproject.toml`、`uv.lock`、`requirements.lock`。

| 模块 | 职责 |
| --- | --- |
| `gateway/main.py`、`http.py`、`pages.py` | 生命周期与健康检查、请求防护/错误响应、页面资产白名单 |
| `gateway/chat.py`、`streaming.py` | 模型/聊天协议、上游请求、流式输出、断连与最终结算 |
| `gateway/admission.py`、`migrations/sql/0006_admit.sql` | 组内调度、尝试限流、持锁批量准入 |
| `gateway/billing.py` | 周期、费用、账本结算、事件与启动恢复 |
| `gateway/accounts.py`、`keys.py`、`operations.py` | 账户/成员操作、Key 签发鉴权、幂等和审计 |
| `gateway/admin/`、`student.py` | 管理与学生 HTTP 路由；共享业务不反向依赖路由 |
| `gateway/static/` | 原生 JavaScript；管理端入口协调加载，各视图使用本次加载的数据快照 |

SDK 自动重试为 0，不跨组回退，不跟随上游重定向，不使用主机环境代理。支持文本及 image_url 图片 Chat Completions、SSE 和客户端函数工具；其他协议及参数边界见[客户端指南](client-guide.md)。

## 准入与账本

PostgreSQL 是身份、权限和资金的权威来源。组锁使用 `FOR NO KEY UPDATE`，兼容外键 Key Share 校验；准入重新读取权限，按组周期、成员周期的固定顺序锁双预算周期，结算采用相同顺序。多 Key 共享 membership 预算；自然日/月按 Asia/Shanghai 划分，数据库保存 UTC。跨周期请求结算原准入周期，预算调整不清除已用费用。

准入函数由 Alembic 安装，不能用 `Base.metadata.create_all` 代替迁移。Python 按组以 2ms 窗口、最多 64 笔合并提交；每笔单独校验，拒绝项回滚，成功项共用一次持久化提交。**提交成功后才能调用上游**。批内使用同一周期/价格时刻，Key 到期按检查时的实时时间判断。

进程缓存最多 4096 条、60 秒的 Key 摘要到组/成员 ID 路由提示，不缓存权限或余额。Redis 在资金锁外记录尝试频率；SQL 再用最新权限、限额及最近 60 秒已接受请求检查。两层限流不可合并删除：Redis 清空不能刷新已接纳速率，Redis 故障也必须拒绝收费请求。

结算保持逐笔事务；有结算等待时最多连续处理 4 批准入，然后让出一次机会。并发统计包含 `running` 和历史 `reserved`；已结束的 `pending` 不占并发。新调用保持 running 到结束，不为中间状态另提交事务；长期高请求率仍可能积压结算并触发并发保护。

## 结束、取消与恢复

最终 usage 有效时结算；缺失/无效 usage、上游错误、超时和断连不能证明免费，进入 pending 等待核对，不占用预算或已结束请求的并发。仅能确认尚未发送的调用按 0 费用结算。请求状态和唯一账本操作保证结算幂等；人工核对的原因、账本、审计在同一事务提交。

结算同时屏蔽 asyncio 和 AnyIO 取消，数据库失败有限重试。失败时保留持久化调用记录，重启将未完成请求转 pending，不能用 TTL 将未知费用算成免费。进程持有 PostgreSQL 会话 advisory lock，明确限制单进程/单副本。

`admission_ms` 包括准入提交，随最终结算保存；崩溃时可能缺失。`total_ms` 不含后续结算提交，SSE 结束不等于账本已提交。每 15 秒下发保活注释，不计为首有效输出。

## 计价与安全边界

金额为整数微元，价格为微元/百万 Token。输入未命中、命中、输出三个整数乘积求和后统一向上取整；缓存命中是输入子集，推理量是输出子集，不重复累计。调用固定引用准入时价格版本，发布新价格关闭旧版本但保留历史。

准入只检查当前组和个人周期的 spent < limit，不估算输入 Token，也不预留资金。结算按官方 usage 如实记账，允许余额为负并阻止后续超预算请求。并发及未结算调用可能造成超支，这是按已结算费用控制预算的明确取舍。官网导入采用固定高峰价估算，不自动切换时段/节假日，不能承诺与官方账单完全一致。

学生密码用 Argon2，个人 Key 用 HMAC 摘要，上游凭证用 Fernet 认证加密。网页登录会话与 API Key 独立。慢哈希放在事务外；锁内再次核验密码/权限和账户状态，防止重置、禁用与导入竞态。单个开通与批量补齐的冲突策略不同，不能强行合并。

不保存提示词、回答、推理文本、函数参数或原始异常响应。错误响应不回显敏感输入，CSV 防公式注入，来源代理只信任明确配置的地址。软删除及旧状态用于历史归因，演示账户补齐仅在非生产模式执行。

测试、运行边界与少量保留的历史证据见[验证记录](archive/verification.md)；操作步骤见[运维说明](operations.md)。


## 管理端消费查询隔离

`admin/report_queries.py` 为消费汇总、请求列表和 CSV 共享筛选/入账口径；原 `/statistics` 保留兼容。`admin/consumption.py` 在只读可重复读事务中生成合计、分组和每日趋势，`requests?include_summary=true` 在同一快照返回列表和筛选合计。概览按调用开始时间归属，预算沿用原准入周期；两者在跨周期请求场景可能存在时间口径差异，预算卡明确标记当前周期。

查询按已入账 Call 的整数 cost 汇总，不叠加项目/个人双账本，不使用当前价格重算历史。费用组成读取 Call.price_id 的历史费率，Decimal 字符串保留分项精度，仍按原计费算法整笔取整。unknown 独立统计；pending 的金额保持 null，绝不按失败或免费处理。

项目测试标签和上游账单核对证据采用既有 Audit 中的显式管理事件（`report_test_label`、`bill_verification`），不增加调用热路径字段或数据库迁移。最新标签作用于整个项目；核对标记要求请求已入账且金额一致，仅保存依据，不能改变余额或历史调用结果。Price.estimated=false 和历史人工核对理由均不能自动推导账单已核验。

`admin/people.py` 提供按人分页的统一目录，详情按 student_id 查询成员与密钥。`/budget-status` 只读计算当前额度，包含尚未创建周期账本的对象，不调用 get_period。新样式独立于学生共享样式，通过 admin-ui 作用域加载；学生页面、准入、结算、SSE、限流和凭证模块保持原实现。验证使用独立测试数据库、Redis DB 15 和模拟上游。

管理端浮层集中在 `admin-floating.js`，使用浏览器 Popover 顶层避免表格 overflow 裁剪；挂在所属 dialog（否则 body），保持模态焦点范围。每个作用域最多一个浮层，并在滚动、尺寸变化和触发器移除时重新定位或关闭。`admin-select.js` 复用相同机制。管理端目标浏览器需支持 Popover、ResizeObserver 和容器查询；旧浏览器不使用额外 z-index 降级。

消费下钻只保存当前标签页内的筛选、维度、分页和滚动快照；刷新浏览器后恢复默认本月，不持久化管理员查询上下文。模型候选读取历史价格与调用模型并集；项目本月消费通过一次聚合读取，沿用已入账 Call 的开始时间口径。这些查询均受现有管理员鉴权保护，不改变准入、计费或账本。


个人和组的 RPM/并发均允许 0，表示不启用该层限制。容量排队只对并发触顶生效，最多等待 10 秒、全实例 32 个等待者；排队重试不重复增加 Redis 尝试数，每轮 SQL 重查预算、身份、权限和配置，断连/取消清理等待名额。频率触顶直接返回带 Retry-After 的 429。

`gateway/files.py` 将官方文件 ID 映射为成员专属的网关 ID；引用前批量校验成员、过期状态和上传凭证版本，再转为官方 ID。上传不创建模型费用记录，模型调用仍使用既有 usage 结算。图片仅在请求及临时文件中传输，数据库保存文件元数据。上传和本地保存无法构成跨服务事务；已知上游 ID 的本地保存失败会尝试删除，异常日志只记录请求 ID。
