# 管理员操作

## 学号导入与学生自助领 Key

在“人员与密钥”页点击“批量添加成员”，或在“项目组”对应行点击“批量添加成员”（自动选中该组）。每行填写 `学号,姓名`，也可从 Excel 复制学号、姓名两列直接粘贴，支持中文逗号。点击“预览名单”核对后，统一设置本批新增成员的个人预算、周期、允许模型、到期时间和初始密码方式，再点击“批量添加”。切换项目组会自动带入该组允许的模型。每批最多 100 人，学号保留前导零；名单内重复学号和格式错误会提示具体行。

已有同组成员会跳过，保持原设置；已有账号加入新组继续使用原密码。学号与已有姓名或身份冲突时整批回滚，并提示名单中的位置及学号，修改后可重新提交。结果列出每位成员的添加状态和登录方式，随机临时密码仅首次成功响应显示。默认每人预算为 0，管理员应按需要设置；组总预算仍单独生效。

“学生账号”页的“批量导入学号”共用同一流程，并保留每行只填学号的简化格式。单人及公共脚本仍可通过“添加人员”开通。

导入只创建账号和成员关系，不预先创建个人 Key。重复导入不会重置现有密码、成员预算或 Key；要调整现有预算，使用“人员与密钥”页的预算调整。相同操作重试不会重复开通，随机初始密码只在首次成功响应显示，不写入审计或幂等结果。

测试可选择“学号作为初始密码”；正式环境必须选择随机临时密码，以免他人凭已知学号抢先领取账号。学生访问 `/student`，首次登录必须改成至少 8 字符的新密码，才能领取 Key。服务器同时执行此限制，不能通过直接调用接口绕过。学生不能修改项目组、预算、模型权限或其他人的 Key。

## 人员筛选、账号搜索与分页

“人员与密钥”页在成员表格的“项目组”表头内可选择“全部”或指定项目组，成员与个人密钥列表会同时按该组筛选（包含已停用的组）。两张表独立分页，翻动成员列表不改变密钥列表的页码；切换项目组时，两张表都回到第一页。筛选后点击添加人员或批量添加成员会默认选中当前组。

“学生账号”页可输入完整或部分学号、姓名，点击“查询”或按回车搜索；“清空搜索”恢复全部学生。搜索保留学号前导零，不区分英文字母大小写；没有成员关系的学生仍可查到，已删除学生不显示。搜索与清空都会回到第一页。

上述列表默认每页 10 条，可切换为 20/50 条，仅在各表格下方显示一套总数、页码和上一页/下一页。筛选和分页在后台执行，仅请求当前页数据；删除后当前页超出范围时会自动返回最后一个有效页。原有重置密码、预算调整、删除及服务 Key 操作仍可在各行使用。

接口 `GET /admin/api/memberships`、`GET /admin/api/keys` 支持 `team_id`；`GET /admin/api/students` 支持 `q` 搜索学号或姓名。三者添加 `paginated=true&offset=0&limit=10` 时返回 `{total, rows}`，不添加 `paginated=true` 时保留原列表格式。学生分页结果直接包含改密状态，密钥分页结果包含对应成员信息，不返回密码散列或完整 Key。

## 更正学生姓名或学号

在“人员与密钥”的学生行，或“学生账号”列表中点击“编辑信息”，修改姓名、学号后保存。同一学生在所有项目组中的信息会同步更新；原账号内部 ID、成员关系、密码、个人 Key、预算和历史使用记录保留，无需删除后重新添加。管理审计记录 `student_update` 及修改前后的姓名、学号。

更正学号后，学生使用新学号和原密码登录；如果尚未修改初始密码，仍使用原先收到的初始密码，系统不会跟随新学号重设密码。新学号不能占用其他未删除人员的学号，冲突时整次修改不保存。学号按字符串保存并保留前导零。此入口仅修改学生身份信息，预算仍通过“调整预算”修改。

## 忘记密码

学生通过邮箱联系管理员，由管理员核实身份后点击“重置密码”，填写核实记录，生成一次性显示的随机临时密码。通过可靠渠道单独交给该学生；不要把账号重置为公开的学号。重置撤销全部旧网页会话和 API Key，学生再次登录仍必须改密，再领取新 Key；已用与预留预算不清零，已发送的上游请求不因此撤回。

在受限 `.env` 中配置 `SUPPORT_EMAIL=你的联系邮箱` 并重建网关容器后，学生登录页会显示邮件联系链接。系统不发送邮件，不提供匿名自助重置接口。

浏览器访问 `/admin`，管理员账号来自 `ADMIN_NAME`（默认 admin）。演示密码只在本机 `secrets/demo_admin_password`。生产密码由初始化时交互设定，数据库保存的管理员会话只有摘要且有时限；没有学生注册入口。

## 初始化和开通

1. 在“模型与计价”点击“从 DeepSeek 官网更新”，自动获取官方当前模型名称、上游模型名和人民币单价，无需手填。导入使用官方高峰价作为固定的保守估算，保存空闲价、核对日期和来源；详情见下文。特殊计价可用“自定义价格”。模拟的 lab-chat/mock-text 不能用于生产，可从当前列表删除。
2. 创建项目组，填写名称、官方 Key、允许模型、独立组预算、周期及限流。无需填写或查看内部标识，系统自动生成；原有组的标识保持原值。官方 Key 加密保存，不在后续列表显示完整值。
3. 在“人员与密钥”填写姓名、字符串学号、组、个人预算、模型和到期。添加学生后直接开通网页登录，由学生自行领 Key。服务身份选择“公共脚本”，填写唯一服务编号及负责人，服务 Key 由负责人保管。
4. 学生完整 Key 只在学生本人领取成功时显示一次，管理员不能代为签发或轮换。关闭后不能再次读取，若未保存由学生自行轮换。重置登录密码会撤销该学生全部旧 Key 和登录会话，学生使用新临时密码登录、改密后重新领 Key；已用预算保持不变。

前导零学号保留，姓名可重复。单人添加时，相同学号与组已有成员会返回冲突；批量添加时跳过已有成员，均不重复发预算。一个学生可在多组有成员关系，各自 Key 固定归组。

## 轮换、调组与停用

- 更换官方 Key 不影响同学个人 Key；后续调用使用本组新凭证版本，历史保存旧凭证版本引用。
- 轮换个人 Key 时保留成员身份与预算。服务身份可签发额外 Key，仍共享个人预算；学生使用自助领取/轮换。
- 调组：关闭旧成员关系及全部旧 Key，再在新组开通相同学号的新成员。旧历史仍属于原组。不要仅让学生在请求中修改组名。
- 吊销或组停用阻止新请求；已发往上游的调用可能继续执行。
- 同组模型白名单、Key 白名单与成员白名单取交集；没有价格配置的模型也不开放。

## 删除项目组、成员和学生

“项目组”“人员与密钥”“学生账号”列表分别提供“删除项目组”“删除成员”“删除学生”，点击后会提示具体对象及影响范围，确认后才执行。停用用于保留列表中的对象，删除用于将对象移出日常列表。

- 删除项目组：移除该组及组内全部成员关系，撤销相关个人 Key 和组凭证；学生账号及其他项目组保留。
- 删除成员：仅移除此组成员关系并撤销对应 Key，不删除学生账号，不影响其在其他项目组的权限。
- 删除学生：移除该学生在全部项目组的成员关系，撤销全部个人 Key 和网页登录会话；项目组及其他学生保留。没有成员关系的学生也会出现在“学生账号”页，可以继续删除。

删除采用保留历史的逻辑删除：历史请求、费用、预算预留、账本、审计及其关联记录不清空，待核对请求仍需核对，已发送请求可能继续执行。删除后的项目组在历史报表中标注“已删除”，请求记录仍可筛选和导出。删除不退还已用预算，也不自动释放不确定请求的预留。可以重新添加相同组标识、学号或成员关系，新记录使用新的内部 ID，不恢复旧 Key 和旧权限。

管理接口为 `DELETE /admin/api/teams/{team_id}`、`DELETE /admin/api/memberships/{member_id}`、`DELETE /admin/api/students/{student_id}`，需要管理员会话、CSRF 和来源校验。重复删除同一 ID 返回成功，不重复产生删除审计。普通列表隐藏已删除对象；管理员可为组、成员和 Key 列表传入 `include_deleted=true` 查询历史关联。

## 预算与费用

### 官网模型与价格导入

“从 DeepSeek 官网更新”每次请求固定的[官方人民币价格页面](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)，解析页面中的模型列以及缓存命中、未命中和输出的高峰/空闲价格。无需提供官方 API Key，且不发起模型推理请求。该操作只更新计价配置，不改项目组、成员、个人 Key、限额或历史费用；导入不会扩大任何模型白名单。

当前预算引擎使用固定单价，因此导入采用**官方高峰价保守估算**并标注“估算”，不会按时间段及中国法定节假日切换。以 2026-11-14 官网数据为例，元/百万 Token（未命中 / 命中 / 输出）：`deepseek-flash` 高峰为 `2 / 0.04 / 8`，空闲为 `1 / 0.02 / 4`；`deepseek-v4-pro` 高峰为 `9 / 0.30 / 27`，空闲为 `4.5 / 0.15 / 13.5`。空闲时段网关记账可能高于官方实际扣费，需要与官方账单核对。导入依据使用人民币页面，不经美元换算。

价格相同时重复导入不创建新版本；价格变化则结束旧版本并原子发布新版本，在途请求仍按准入时保存的版本结算。取价失败、页面结构变化、币种不符或价格不合法时不写入任何配置，保留原价格。不会后台定时抓取；需要刷新官网价格时再次点击按钮。此操作会用官方价格替换同名模型当前的自定义计价。

“删除模型”结束该计价版本并移出当前列表，没有有效计价的模型会同时从学生 Key 的 `/v1/models` 列表移除。历史计价记录保留供已有请求结算和追溯，在“查看历史计价”中可查；删除不修改既有组白名单，不清空调用及预算账本。再次从官网导入会重新启用官网仍在列出的模型。

接口：`POST /admin/api/prices/import-official`、`DELETE /admin/api/prices/{price_id}`，均要求管理员登录和 CSRF；`GET /admin/api/prices` 默认只列当前有效计价，`?include_ended=true` 包含历史版本。切换真实 DeepSeek 上游仍需在运行环境中配置 `UPSTREAM_URL` 及有效的组凭证，导入价格本身不改变上游地址。

“调整预算”修改当前及后续周期上限，保留已结算与预留，并记录原因。成员与组预算分别设置，组预算不是个人预算之和。日/月按北京时间自然周期，到期新建周期；周期类型在对象创建时固定。

管理弹窗的原因允许填写“测试”等简短说明，不再要求至少 5 个字；去除首尾空白后非空即可，最多 500 字。预算调整、密码重置和人工核对采用同一规则。中文输入法选词、空格和回车换行不会保存或弹出浏览器校验气泡；仅明确点击“保存”时检查表单，错误显示在弹窗内，原因仍进入原有审计记录。

可用金额 = 上限 − 已结算 − 未结算预留。API 按保守输入和最大输出预留，因此余额仍大于 0 时也可能因无法覆盖最大请求而被拒绝。可降低输出上限或适当提高预算。

学生端仅显示各项目组“本月已用（已结算）”，不向学生返回预算上限、预留或可用金额。按北京时间自然月及调用发起时间统计，不受个人限额按日/按月设置影响；后台限额执行和管理员预算账本保持原口径。

“预算账本”同时显示项目组和个人的周期额度、已结算、预留及可用金额。同一调用同时计入组和个人限额，两种归属的金额不能相加作为总费用。

当前连接模拟上游的测试环境提供“清理测试记录”和行内“删除该组测试记录”。选定项目组并输入完整名称确认后，系统在同一事务中删除该组全部模拟调用、拒绝记录、周期预算记录、账本和关联告警；组、学生、成员、Key、官方凭证、价格及预算配置保留，下次调用重新按原配置创建周期账本。该组如有运行中请求会拒绝清理；缺少 usage 的模拟待核对请求可以一起清理。操作写入管理审计。其他项目组不受影响。

清理接口为 `POST /admin/api/teams/{team_id}/clear-test-usage`，请求包含 `confirm_name`。只在非生产模式且上游明确指向本项目模拟服务时开放，连接真实 DeepSeek 或正式环境时不提供该入口，避免将真实账目作为模拟用量清空。升级本身不会执行清理。

待核对请求保留预留，保守占用并发名额；超时不自动退款。先查官方可取得的账单/后台记录和网关时间、组、模型、请求 ID，再在请求记录中“人工核对”填写核实金额与依据。0 元也必须有核实依据。调整在原准入周期记账，原因和审计保留。上游实际费用超预留时真实入账，余额可以为负，不会人为抹平。

## 记录与追溯

管理员侧边栏的“记录与追溯”下设四个标签页：请求记录、拒绝记录、告警与待办、管理审计。记录页默认每页 10 条，可切换为 20/50 条；表格上下均显示总条数、当前页/总页数、页码及上一页/下一页。翻页替换当前记录，不追加长列表；更改筛选或每页条数会回到第一页。

### 请求记录与统计口径

请求记录保存通过准入的调用，用于查询用量、费用及人工核对。支持时间、组、人员、Key ID、模型、请求 ID、调用结果和结算状态筛选。详情包括上游请求 ID、Token、缓存命中、计价版本及耗时。CSV 包含调用结果、原因及 Token 计数，页面从当前筛选的首条导出，最多 10000 行；更多数据按时间段或 API offset 分页导出。无时区的时间按北京时间解释，结束时间不包含该时点。费用单位为微元，页面显示人民币；估算费用需与官方账单核对。

调用结果与费用结算状态相互独立：

| 维度 | 状态 | 含义 |
| --- | --- | --- |
| 调用结果 | 执行中、成功、上游失败、客户端断开、未发送、结果未知 | 网关观察到的执行情况；超时或重启不能推定上游没有执行 |
| 结算状态 | 已预留、待核对、已结算 | 是否拿到可信 usage 或已经人工核实金额 |

例如，收到完整回答但缺少 usage 的调用可以“成功 + 待核对”；上游报错的调用在人工核实金额后可以“上游失败 + 已结算”。人工核对不会改写调用结果、调用失败原因或原结束时间。流式响应未观察到模型完成标志（finish_reason）或最终有效用量时保留结果未知；流中断即使已有 usage 可结算，也不计为成功。

使用概览按组、人员、Key、模型分别统计上述调用结果。失败只统计已确认的上游失败，不再用“总数减成功数”推算；待核对单独统计，不能与调用结果各栏相加。已准入调用不包含拒绝记录。

升级前的历史调用缺少独立结果信息，统一标为“结果未知”，保留原费用、Token、结算状态及预算账本，不反推历史成功数。

### 拒绝记录

记录 `POST /v1/chat/completions` 在准入前被拒绝的尝试，包括预算、RPM/并发、权限、无效或过期 Key、参数校验、过大请求以及依赖服务异常。每次拒绝保存独立请求 ID、时间、可识别的人员/项目组/Key、模型、HTTP 状态、原因和来源 IP；预算拒绝标明首先阻止准入的组或个人限制，频率/并发可标记“两者”。过大或无法解析的请求可能没有模型信息，未知 Key 无法归属人员。

拒绝不创建预算预留或费用，不会与已经准入后上游报错的调用重复统计。页面支持时间、项目组、人员、Key、模型、原因、请求 ID 筛选，显示匹配的总次数。API 为 `GET /admin/api/rejections`，返回 `total` 与 `rows`，支持 `offset/limit`。请求、告警及审计接口添加 `paginated=true` 时也返回筛选后的 `total` 与当前页 `rows`；未添加时保留原列表格式，CSV 导出不受页面条数限制。

拒绝记录从升级后开始累计，不能从历史去重告警还原次数。数据库不可用时可能无法持久化拒绝，系统保留安全错误日志与本次运行的 `rejection_record_failures` 指标，并在概览提示统计缺口；不将内存计数当作完整历史。

### 告警与待办

新来源是“提示”，预算阈值、频率/并发拒绝等是“预警”，费用待核对、实际费用超出预留和恢复事件是“待办”。新 IP 不代表违规。常规重复事件按小时汇总首次/最近发生时间及次数，预算阈值按周期去重，单个待核对请求按请求 ID 去重。历史事件初始次数为 1，不代表升级前的真实发生次数。

默认显示待处理事项，可切换已处理或全部。告警可直接跳转对应请求核对，拒绝类告警可跳转同组同原因的拒绝记录。处理记录保留处理人、时间和说明，手动处理同时写管理审计；同一小时再次发生的拒绝会重新打开告警，旧处理说明仍可在审计中查到。

“标记处理”只记录处理结果，不释放预算、不结算费用。关联请求仍待核对时服务器拒绝直接标记处理；应先通过“查看请求 / 核对”填写核实金额与依据。结算完成后关联的费用待核对告警自动处理。重启恢复的汇总待办须在全部待核对请求处理完毕后手动关闭。

### 管理审计

记录管理员登录、开通、吊销、上游轮换、预算/价格变更、人工核对、告警处理，以及学生自助操作。预算和项目组配置变更保留非敏感字段的修改前后值。当前管理员操作使用配置的管理员名称，共享账号无法区分实际操作人员。

调用与拒绝记录中的原始 IP 按 `RETENTION_DAYS` 由运维任务清理；不保存完整 API Key、提示词和回答。删除人员或项目组保留历史记录；模拟环境的“清理测试记录”会一并清除选定组的拒绝记录，管理审计保留。

个人 RPM/并发可通过开通 API 的 `rpm`、`concurrency` 指定（默认 20/2）；组参数在创建时指定并可经组 PATCH 管理接口修改。管理 API 需要登录 Cookie 与 `X-CSRF-Token`，个人 Key 不具备管理权限。首版页面提供常用操作，全部参数与 API 定义见 `gateway/schemas.py` 和 `gateway/admin/`。
